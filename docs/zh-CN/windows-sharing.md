# Windows 共享预览

[English](../windows-sharing.md) · [路线图](roadmap.md)

v0.3.0-alpha.1 开发版加入 Windows 共享角色。在原应用中打开“共享此设备”，
开始后共享当前正常登录桌面的主显示器。仅打开页面不会开启监听或采集。

alpha.2 已加入 [Mac 控制端源码预览](mac-controller.md)，便携传输/状态检查通过，Mac 原生验收待完成。
可用 Windows 控制端手填目标IP验证 Windows 共享，
这不代表 Mac → Windows 已可用。原 Windows → Mac 及该控制角色中的剪贴板功能继续保留。

## 使用与密码

- 开始共享后，连接方填写本机局域网 IP 与密码；两端需要 TCP 47980 可达。
  必要时在 Windows 防火墙允许应用使用专用网络；应用不自动修改防火墙策略。
- 首次生成 12 位随机密码。查看/复制不改变共享状态；修改支持 8–64 位英文字母、数字与符号，
  不含空格。自动生成仅填写草稿，取消保持原密码。
- 保存使用当前用户 DPAPI 加密及原子替换，成功后停止旧共享并释放已按下的输入。
  再次开始共享时使用新密码。保存失败保持旧密码与连接；共享密码独立于目标设备的连接记忆。
- 停止共享或退出主应用会结束监听与连接；切换页面继续共享。主应用关闭会等待共享清理。
  登录/重新打开不自动共享；初版界面中的控制与共享角色互斥。

## 画面与输入

复用现有 FFmpeg 依赖，通过 GDI 采集桌面、Media Foundation 的 `h264_mf` 硬件编码，
数据仅经内存/管道实时传输，不生成录像文件。流畅目标不超过 720p/30，标准/高清不超过
1080p/60，以码率区分；不放大小显示器。这是配置目标，不代表持续性能已经验收。

FFmpeg 构建或硬件不支持时，停止共享并勾选“兼容编码”，使用两线程 `libx264`，CPU 占用较高。
采集错误会结束连接并保留重试入口；`IDesktopCapture` 便于后续替换为 DXGI/原生 MFT。
通过 FFmpeg 使用硬件编码，不等于整个采集/渲染链路已原生采用 D3D。

Windows 共享端先发布 `platform=windows` 与 `inputModel=win-vk-v1`，再发送画面。
使用 Windows VK 与明确的修饰键按下/抬起事件；不把 Control 默认为 Command。
Windows 控制端面对 Windows 目标时保留原生 Ctrl 快捷键，面对 Mac 时保留原有映射选项。
主屏归一化指针转换到完整虚拟桌面的 SendInput 坐标；无坐标的滚轮保留当前鼠标位置。
非法输入拒绝，断开/失败先释放按键和鼠标，再等待编码进程退出。

## 验证与范围

独立认证/加密包、真实 DPAPI、未认证不采集、单连接、非法输入、故障清理、真实 WPF 密码/共享流程，
以及 Windows 目标快捷键路由已验证；真实 Windows 桌面 → 硬件 H.264 → 加密回环 → 解码已通过。
参见[检查记录](../../tests/results/windows-sharing-2026-10-10.txt)。

输入状态测试使用记录适配器。可选原生 SendInput 测试只针对自建测试窗口，带前台窗口保护；
本环境拒绝测试窗口获得焦点，因此未确认系统事件实际接收。提交成功也不等于每个应用都接收。
真实局域网、Mac 控制端以及较长采集/延迟测试仍待验收。

此共享角色暂不传剪贴板/文件、不发布 Windows Bonjour；双角色互通后的 beta.1 再接入。
仅主显示器，不保证锁屏、登录前或 UAC 安全桌面控制；输入受到 Windows 进程完整性等级限制，
应用不自动提权或绕过系统规则。
