# 文件复制粘贴（开发更新）

[English](../files.md)

主分支已实现文件剪贴板共享，已发布 v0.1.0 安装包没有此功能。Windows 加密模拟端/真实客户端界面及 Swift 便携测试通过，Mac 原生和真实两机验收仍待完成。

## 使用

1. 两端更新，使用已有配对密钥正常连接。
2. 文件共享默认开启，曾主动关闭则保留关闭状态。两端均在“设置 → 剪贴板 → 同步文件”调整，等待 Windows 菜单显示已启用。
3. 在资源管理器或 Finder 复制文件，自动开始传输；显示就绪后在另一端的 Finder/资源管理器粘贴。

两端会记住文件共享选择，不再输入密码、重新配对或逐文件确认。开启或重连不会发送剪贴板已有内容，请就绪后重新复制。允许范围是经过认证的远控连接，不是局域网任意设备。

Windows 勾选“Windows 快捷键”后，Ctrl+C/V 映射为 Mac Command+C/V，远端快捷键先点击画面启用。
Windows 向 Mac 传文件时，提前 Ctrl+V 会提示等待，并阻止粘贴旧内容；完成后再按一次。
不会延迟自动执行粘贴，以免这时 Mac 焦点已经变化。Windows 本地应用的粘贴由系统处理，同样等接收就绪后再操作。

## 范围

- 普通文件，包括图片、文档、压缩包，支持一次复制多个文件；直接复制图片像素不是文件格式，暂不支持。
- 每次最多 32 个文件，单文件 4 GiB，单批 8 GiB。
- 暂不支持文件夹、符号链接、没有真实本地路径的虚拟文件；文件夹可先压缩再传。
- 文件名须兼容两端：不能含路径分隔符、Windows 保留设备名、末尾点/空格或忽略大小写后重名，上限 240 个 UTF-8 字节。无效批次报错，不偷偷改名。

同时只运行一项文件任务。新本地复制可取消旧任务。剪贴板只在界面线程访问，文件读写、校验及网络在后台。
32 KiB 分块，不整文件读入内存；发送按实际耗时控制在持续目标 8 MiB/s，允许起始 512 KiB 小文件快速发送；磁盘/网络已经消耗的时间计入预算，不逐块固定等待。目标与短时突发不是实测局域网速度保证。独立连接避免文件内容进入键鼠/视频队列，但仍共享局域网带宽。

## 进度、取消与保存位置

两端显示百分比、已传大小和平均速率，并有取消入口。字节发完后仍显示校验/准备剪贴板，接收端确认就绪才提示可粘贴；Windows 剪贴板忙时最多重试两秒，失败时提示从接收目录取用。取消、断开或撤销允许会关闭文件连接，正常清理删除未完成批次；接收等待上限 15 秒、任务上限一小时，Mac 单次发送等待还限制为三秒。完成批次保留，即使最终无法写入剪贴板。

接收端校验长度和 SHA-256 后才将独立临时目录转为完成目录，不覆盖旧批次，不接受对端指定保存路径。
接收时若你新复制了内容，会保留新的剪贴板；Windows 剪贴板忙时最多重试两秒。收到文件不会再次回传。文件剪贴板只表示复制，不删除源文件。

在两端“设置”菜单选择“打开接收目录”即可查看：

| 平台 | 位置 |
|---|---|
| Windows | `%LOCALAPPDATA%\LocalRemoteDesktop\ReceivedFiles` |
| Mac | `~/Library/Application Support/LocalRemote/ReceivedFiles` |

每批有独立目录，已完成文件不会自动删除，使用完可自行清理，注意磁盘占用。崩溃或系统强制结束可能留下 `.incoming-*` 未完成目录；退出该设备的 Local Remote Desktop 后可清理这些目录，完成批次不受影响。

## 连接与隐私

除桌面端口 47980 外，还需允许 TCP **47981** 到 Mac。独立文件连接自动复用配对密钥双向认证并以 AES-GCM 加密，另检查本次桌面会话令牌和最新允许状态。过程在后台完成，不需要再次人工认证；桌面断开即失效。旧 Host 不支持时仅关闭文件功能，仍可远控。

只向配对设备发送选中的文件内容及文件名，不发送完整源路径，文件路径不混入文本同步，不记录文件内容。
接收文件须保存到磁盘，Local Remote Desktop 不额外做静态文件加密。文字与文件有独立允许选项。
设计借鉴“先准备文件信息，再传内容”，不代表兼容 LocalSend 的通信协议。详见[协议](protocol.md)和[验证状态](validation.md)。
