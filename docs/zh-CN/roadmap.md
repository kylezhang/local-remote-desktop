# 路线图

产品与仓库已更名为 **Local Remote Desktop** / `local-remote-desktop`。
见[命名与兼容说明](product-name.md)。

[English](../roadmap.md) · [README](../../README.zh-CN.md)

目标是各平台安装同一个产品的对应版本，通过统一界面发起或接受局域网远程控制。接受连接必须授权，发现设备不代表信任。

v0.1.0 保持正式基线。当前测试版为 v0.2.0-beta.1：已测试 Windows 包与 Mac 源码，Mac 原生验收待完成。它合并原有补丁计划和新剪贴板/密码功能；测试版不代表 v0.2.0 全部功能完成，不承诺正式版日期。

测试版打包及正式版门槛见[发布检查清单](next-release.md)。

v0.2.0 的可选文字/普通文件剪贴板原型已在主分支实现，并通过便携/Windows 加密模拟端测试，Mac 原生验收待完成。
已有发布版本不变，不代表 v0.2.0 整组功能已完成。

## 版本计划

多端遵循[界面与交互规范](interface.md)：统一词汇与流程，保留原生控件及各系统键盘习惯。

| 版本 | 重点 | 计划功能 | 发布标准 |
|---|---|---|---|
| v0.1.0：已发布 | 首个可用版本 | Windows → Apple Silicon Mac，同会话控制、配对加密、连接记忆、全屏、重连、画质切换及诊断 | 已发布基线；验证范围见下文 |
| v0.1.1 计划：并入测试版 | 安装与更新可靠性 | 已确认的蓝莓蓝紫品牌、图标打包、清晰的权限入口、完整替换/保留权限选项；改善签名和钥匙串更新行为 | Mac 原生构建及安装/升级验证，Windows 安装包检查通过，说明签名和授权行为 |
| v0.1.2 计划：并入测试版 | 输入与流畅度 | 键盘布局及数字小键盘、焦点/修饰键释放、断线清理、休眠唤醒恢复；测量并降低输入和画面延迟 | 可重复的真实两机验证，无修饰键卡住，有延迟基线并验证恢复 |
| v0.2.0-beta.1：测试版 | 当前实现快照 | Windows 包、Mac 源码、短/手填密码、文字/文件剪贴板、输入与界面改进 | 最终 Windows 包回归及校验通过；明确限制，不发布未验证 Mac 二进制 |
| v0.2.0 | 日常使用更方便 | 局域网自动发现、明确配对和撤销、可选且有大小限制的文字/普通文件剪贴板共享、英文界面及中文本地化 | 发现不能绕过配对，剪贴板在已配对会话默认开启、记住撤销且限量，两种语言验证 |
| v0.3.0 | 桌面双向控制 | Windows 被控端、Mac 控制端；每个桌面应用统一提供“连接设备”和“允许连接” | Windows ↔ Mac 实机验证，授权、断开释放和会话延续通过 |
| v1.0.0 | 稳定桌面版 | 整理现有桌面功能，完善安装包、升级、引导、支持系统列表和回归验证 | 两个桌面方向达到发布标准，原生构建和签名分发验证通过 |
| v1.1.0 | 手机控制端 | Android 优先：连接 Windows/Mac，适配触摸、文字输入和小屏导航 | 手机到桌面实机验证和显式授权；不包含手机作为被控端 |
| v1.2.0 | 扩展移动端 | 经平台验证后增加 iOS/iPadOS 控制端，优化平板交互 | 先验证技术及分发可行性，再确认版本范围 |
| v1.3.0 | Linux 桌面版 | Linux 控制端和被控端，与 Windows/Mac 互通；明确支持的桌面会话和安装包 | 在支持的真实 Linux 系统上验证采集/输入权限及双向控制 |
| v1.4.0 | HarmonyOS 控制端 | 原生手机/平板控制端，连接支持的 Windows/Mac/Linux 被控端；适配触摸、文字输入和配对 | 原生 SDK、权限、分发及真实设备互通验证通过；不包含手机作为被控端 |

Linux 和 HarmonyOS 都是版本目标，尚未支持。HarmonyOS 桌面控制需独立评估，v1.4.0 先覆盖手机/平板控制端。普通文件剪贴板共享归入 v0.2.0；文件夹/虚拟文件、多显示器和音频暂不安排版本。

移动端共享画面、经授权接受远程操作作为额外能力研究，暂不分配版本号。
先做控制端不意味着永久排除手机共享，见[移动端共享可行性](mobile-sharing.md)。

## 验证与前提

### v0.3.0 实现顺序

双向桌面控制是 v0.2.0 日常功能收尾后的下一项核心能力：补齐 Windows 被控端和 Mac 控制端。
继续使用原生应用及局域网协议，按模块渐进调整。

1. 逐步从 Windows 窗口中分离连接和会话管理，每一步保留 Windows → Mac 回归。
   控制端/被控端是会话角色；每个平台仍只有一个应用，提供“连接设备”和“允许连接”。
2. **v0.3.0-alpha.1：**Windows 采集、H.264 发送及已授权的输入接收。
   先用回环控制器实测 Windows 链路，检查有界队列、停止/重启和权限失败。
3. **v0.3.0-alpha.2：**Mac 解码显示、鼠标坐标和键盘发送。
   在真实 Mac/Windows 验证画面和普通键鼠；发送输入前明确能力协商及随目标系统变化的快捷键映射。
   现有 Windows 虚拟键码和 Mac 修饰键语义还不是完整的平台无关输入约定。
4. **v0.3.0-beta.1：**统一连接/共享界面，让发现、剪贴板授权适配两种角色；
   两方向验证撤销、重连、画质切换及资源释放。文件监听随被控角色，而非永久绑定 Mac。
5. **v0.3.0：**两方向通过原生验收，并确认已有 Windows → Mac 功能可用后正式发布。

复用认证加密格式、H.264 传输、文件规则和兼容性测试；Swift/C# 保留各自平台实现，
并非共用一个二进制模块。发现设备不能直接授权控制；开启共享不自动建立反向控制连接。
首轮不以两台互相同时控制为验收目标。alpha.1 的 Windows 共享端已在主分支实现，
实际桌面加密回环及界面回归通过；原生输入接受、Mac 控制端与两机局域网验收尚未完成。
详见 [Windows 共享预览](windows-sharing.md)。alpha.2 已加入 [Mac 控制端源码预览](mac-controller.md)
及传输/状态自动检查；真实两机的原生验收与后续角色互通仍待完成。

v0.1.0 已验证 Windows 构建及模拟被控端测试，用户反馈真实 Windows→Mac 流程可用；这不能代替独立复现的 Mac 原生测试。详见[构建与验证状态](../validation.md)。

正式 v0.2.0 必须区分稳定签名分发和 ad-hoc 开发构建。稳定签名需要合适的签名身份，面向更广泛的 macOS 分发可能还需公证。权限和钥匙串行为必须结合实际安装签名验证。脚本可以定向重置本应用的授权决定，不能自动授予权限，也不能保证系统设置中的条目消失。

日常签名升级以避免不必要的权限重置和重复钥匙串提示为目标；首次授权或系统要求的重新授权仍可能发生。硬件解码/渲染是否替换，以 v0.1.2 的性能测量为依据。

## 版本及发布规则

- 补丁版本（v0.1.1、v0.1.2）改善现有 Windows → Mac 流程，不增加平台，不主动破坏协议或存储兼容性。
- v0.x 阶段，新功能组使用次版本（v0.2.0、v0.3.0）；若有不兼容改动，必须注明并验证迁移方案。
- v1.0 起：补丁版本修复问题，次版本增加兼容功能，主版本承载不兼容改动。
- 应用版本、更新日志、AtomGit tag、Release 说明及产物命名保持一致。Mac 内部构建号可独立递增。
- 不移动已有发布 tag、不覆盖发布产物；明确区分规划、主分支未发布改动及已发布功能。
- 未达到发布标准时继续修复或明确调整范围，不宣称完成。详见[发布流程](../releasing.md)。

## 边界

局域网优先，不做账号、公网穿透或中转、云中心服务。共享正常登录后的当前桌面，不创建独立远程会话。不承诺绕过 FileVault 预启动或通用的锁屏/登录界面控制。移动端先作为已授权桌面的控制端，不默认支持手机无人值守被控。安全和可靠性优先于平台数量。
