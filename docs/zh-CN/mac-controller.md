# Mac 控制端预览

[English](../mac-controller.md) · [Windows 共享](windows-sharing.md)

开发版 **v0.3.0-alpha.2** 在同一个 Mac 应用内加入控制端。源码已实现配对连接、
H.264 接收与 VideoToolbox 解码、键鼠发送、全屏、画质切换和断线重连。
传输和状态自动检查通过；**Apple SDK 原生构建、AppKit 操作、VideoToolbox 画面
和真实 Mac → Windows 验收仍待完成**。这是开发检查点，尚不代表双向互联已验收。

## 连接 Windows

1. Windows 打开“设置 → 允许连接（预览）”，开始共享并查看共享密码。
   共享密码与保存的目标设备密码相互独立。
2. Mac 若正在共享，先停止共享；再打开“设置 → 连接设备（预览）”。
3. 填写 Windows 的“目标 IP”（局域网 IPv4）及共享密码，点击连接。
   两端需能通过 TCP 47980 通信；点击画面后获得键盘焦点。
4. 断开或关闭控制窗口会释放输入并结束连接。

记住上次成功连接的地址。控制端密码只保存在 Mac 应用运行期间的内存中，
关闭再打开控制窗口仍保留；退出应用后需要重新填写，不写入磁盘，也不新增或访问钥匙串项。
Mac 仅作为控制端连接时，无需屏幕录制或辅助功能权限；共享这台 Mac 的桌面时才需要。

## 操作

- 默认开启“Mac 快捷键”：Command 对应 Windows Control，支持 Command+C/V/A/Z；
  物理 Control 对应 Win，Option 对应 Alt，Shift 保持 Shift。关闭后 Command 对应 Win，
  Control 对应 Control。切换映射会释放已按下的输入。
- F11 切换全屏，Control+Option+Escape 释放远程输入。
  macOS 仍可能接管 Command+Tab 等系统快捷键，不做全局拦截。
  当前按键映射针对常见物理键位，国际键盘布局和输入法组合输入仍待验收。
- 支持鼠标移动、左右中键、拖动和垂直滚轮；排除黑边，拖动越界时限制到画面边缘。
- 流畅、标准、高清沿用 Windows 编码档位。切档后关闭旧连接，等待三秒供共享端清理，
  再按最新档位连接一次；关闭自动重连也可切档。
- 自动重连仅用于已成功连接后的故障。首次失败、认证或能力拒绝、无效视频、输入积压
  需要主动重试。断开、关闭窗口或关闭正在等待的自动重连都会取消重试。
  目标端在连接关闭时释放已按下的输入。

## 实现与验证

沿用 RMP1 和旧 RML1 双向认证与加密记录。发送输入前检查目标能力。
单个发送线程，待发送消息最多 256 项，相邻鼠标移动合并；积压时断开连接，
释放所有输入时清除待发送输入。视频记录最大 8 MiB，尺寸最多 4K 面积。
Annex B 解析并转换 SPS/PPS 与访问单元供原生 VideoToolbox 解码；待呈现画面只保留一帧。

[检查及精确范围](../../tests/MacControllerChecks/README.md)使用独立 Python AES-GCM 测试端、
生产 Swift 传输/会话/状态代码及明确的平台适配替身。Linux 通过 OpenSSL 适配器替代
原生 CryptoKit/CoreGraphics，不代表真实解码或系统输入已验收。
剩余门槛见[验证状态](validation.md)。

## 范围

单控制端、Windows 主显示器、已登录的当前桌面；不保证 UAC 安全桌面、提权应用输入、
锁屏或登录前控制。反向角色预览尚无剪贴板/文件同步、Windows 发现广播和 Mac 控制端
密码持久化，属于后续角色互通阶段。原 Windows → Mac 方向的文字/文件功能仍保留。
界面禁止同时共享与控制，避免相互共享造成画面反馈。
