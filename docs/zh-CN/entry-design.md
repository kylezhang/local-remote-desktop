## 页面与操作

首次打开先选 **发起连接**（操作另一台设备）或 **接受连接**（让另一台设备操作本设备）。
选择仅进入对应页面，不立即联网、不立即共享。仍是一个应用内的两个用途，首页
没有常驻侧栏，也没有 IP、密码、设备列表等表单。

| 页面 | 内容与主要操作 |
|---|---|
| 首页 | 两个明显、同等重要的大入口；设置为次要入口。 |
| 发起连接 | 设备列表、刷新、唯一的“添加目标”入口；点击目标或添加时才弹出配对表单。空列表给出操作提示。 |
| 接受连接 | 本机名称、IP、隐藏的密码竖排；“接受连接”在本页底部，信息确认后再操作。 |

返回只回到用途选择页，不清除密码和记录，不停止正在进行的共享。浏览“连接”页
不会结束共享；真的连接目标前，按现有单角色规则确认“停止接受并连接”，取消则
保留共享。导航、停止共享与断开连接分别对应不同操作。

本提议针对**首次打开**，不意味着每次打开都强迫重选。再次启动的规则仍待评审，
可以考虑记住上次用途；已有会话需保留可见的停止/断开入口。草图刷新会重置，
不保存任何用户设置。

## 用语与图形细化

用户指出“被连接”与页面内“共享”混用会造成理解困难。本轮草图改用一组连接用语：

| 位置 | 中文 | English |
|---|---|---|
| 操作其他设备的入口 | 发起连接 | Start a connection |
| 接收其他设备访问的入口 | 接受连接 | Accept connections |
| 本机开启操作 | 开始接受连接 | Start accepting connections |
| 本机停止操作 | 停止接受连接 | Stop accepting connections |
| 远程会话建立/结束 | 连接 / 断开 | Connect / Disconnect |

配对和授权规则不变，不表示无需密码。内部代码仍可使用共享角色名称，界面无需
再引入该概念；文件剪贴板用“同步文件”。状态在对应页面区分尚未接受连接、等待连接
和已连接。入口名称已于 2026-10-12 确认，整套视觉方案仍待评审；尚未修改原生客户端。

首页仅保留主标题，删除解释性小标题和卡片说明。每个入口的图标和文字作为一组
居中。两幅图都以前景左下屏幕表示本机、后景右上灰色屏幕表示另一台设备。弧形
连接路径表达谁发起连接，不代表画面数据流向；指针落在被操作的屏幕内：
发起时在远端，接受时在本机。圆角屏幕和配色呼应主 logo，功能插图不另造应用 logo。
标题栏小图标继续遵守平台习惯。

## 内容与状态

设备名称和平台来自设备发现、认证后的目标信息或保存记录，不从 IP 猜测。草图
中的本机与目标是不同设备；原生发现应排除本机。未知手动地址在获得目标信息前
只显示地址。用途选择不引入新账户、认证步骤或协议。

本机 IP 由系统提供，可复制，不当作应用配置编辑。多接口/VPN 地址沿用原生可达
地址的选择规则。密码默认隐藏，修改在独立草稿中完成：8 位、自动生成按钮明显；
取消不改密码，保存停止共享，等待再次明确开始。现有长密码不会自动截断。
查看、复制、安全存储和同步同意范围沿用现有实现规则。

Mac 权限缺失时，在“接受连接”页面出现对应操作，不在首页或连接别人的表单中出现。
仅进入页面不请求钥匙串或系统权限；授权由系统管理。设置仍按通用、连接设置、
剪贴板和关于分类，草图中的小面板只示意既有范围，本轮不另做设置规范。

## 视觉与预览范围

沿用已确认图标、#5265EC 配色、白灰内容与系统字体。Windows/Mac 结构和用语一致，
保留各自原生标题栏。草图窗口为 560 × 568 逻辑像素，内容边距 22 × 28；不常驻
侧栏、不显示第二列凭据。具体原生最小尺寸及缩放仍需验收。正常内容能完整显示，
额外授权提示或长内容可滚动，共享主要操作保持可达。

PNG 来自浏览器预览，不是原生客户端截图。草图覆盖中英文、平台外观、空列表、
密码错误、8 位草稿/生成/取消/保存、明确接受连接、待授权和角色冲突。设备、密码
均为虚构；复制、刷新和权限按钮只提供模拟反馈，不联网、不读写剪贴板、不保存
凭据、不操作系统。

## Mac 仍显示旧界面的核对结果

已核对 c0582fe 源码：`Package.swift` 构建 LocalRemoteDesktop；`App.swift` 将
DesktopShell 作为窗口根视图，默认进入连接页。HostView 只在共享页内使用，并配有
底部 SharingActionView。构建脚本打包该 SwiftPM 产物，安装脚本在构建、签名预检查
后更新 `/Applications/Local Remote Desktop.app`。这条源码入口未发现旧单独 Host
页面作为根视图。

**用户 Mac 实际安装和运行的程序仍未核实。** 构建失败或新旧签名不兼容会保留旧
应用，运行中的旧副本或另一份源码目录也可能导致该现象；这些只是候选原因。
同一个 alpha.2 版本标签无法证明构建提交。源码内部构建号为 23，安装值尚未知。
不能用推送成功或 Windows 构建成功代替 Mac 更新成功。

下一实现阶段应提供不含秘密的源码/构建标识，并比较构建、安装、运行的程序路径。
保留 bundle 和钥匙串身份，不把重置权限作为界面修复。本轮未连接 Mac SSH，也未
做 Mac 原生验证。

## 首页观感细化 — 2026-10-12

用户认为此前直白的屏幕与箭头示意仍不够像成熟产品。本轮将设备改为前后叠放，
以轻微表面层次、圆角轮廓和弧形连接路径构成完整插图；品牌蓝集中在方向与操作
指针上，不加大面积发光，也不限定为 PC 外形。插图不是新的应用 logo。

入口改用浅中性色操作区，替代大白框。主标题/入口字号为 24/20px，字重 500；两个
入口同等突出，176 × 130.24 插图居中，图文间距 15px。窗口保持 560 × 568，导航、
凭据表单和角色状态逻辑不变。悬停/按下/焦点样式分别定义，不加自动动画；首页
重复样式合并为可读的独立部分。

本轮浏览器核对两端中英文首页、英文单行显示、矢量资源加载、内容完整及图文精确
居中；Tab 导航的可见焦点已验证。悬停/按下规则已检查，未做真实鼠标或原生客户端
测试。历史窄窗口检查对应上一版草图，本轮更新的窄窗口规则尚未另设视口实测。

## 整体协调细化 — 2026-10-12

保留已确认的插图方向和入口名称，将标题/操作区间距收紧为 26px，图文间距为 13px，
两个入口间距为 18px；统一轻边界及 18px 圆角。设置改为带文字的次要入口，三页
保持相同右上基线。齿轮图形重新居中，设备列表采用相同圆角屏幕语汇；后续页面
和对话框标题沿用首页的中等字重，避免各处争夺视觉重点。窗口尺寸及连接、配对、
权限逻辑均不变。

浏览器复核三页 × 中英文 × 两端外观，共 12 种默认布局：内容完整、每页仅一个
设置入口。首页可进入对应任务页，新的设置入口能打开既有预览面板。截图是浏览器
草图，不代表原生客户端验收。空列表/错误情形图片仍为此前截图，不混称本轮成稿。

## 设计自查责任

交给用户看之前，开发方应先完整检查用语、设备身份、连接方向、被操作设备、
操作与确认状态、中英文长度、视觉居中、图文间距、悬停/按下/键盘焦点反馈及窄
窗口表现。不让用户逐项发现对齐或状态错误；用户主要确认产品与设计方向。用途
选择只导航，不授予控制、不结束既有会话；原生验证证据单独记录。
