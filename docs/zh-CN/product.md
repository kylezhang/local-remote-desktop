# 产品方向

[English](../product.md) · [版本规划](roadmap.md) · [界面方案](design.md)

## 要解决的问题

项目起源于一个个人办公需求：在 Windows 台式机上直接操作 Mac，减少在两台
电脑之间来回切换。尝试过的工具有些操作不顺手，有些版本陈旧；对于这个简单的
个人需求，也不太希望额外承担付费成本。借助 AI 辅助开发，围绕实际工作流程
做一个连接简单、日常好用的局域网工具。

## 最终产品形态

**Local Remote Desktop 是每个平台一个应用，用来在局域网中操作另一台设备
当前的桌面。** 桌面设备既能连接其他设备，也能明确开启自己的共享。
被控端、控制端是连接中的角色，不是用户需要分别安装、理解的两套产品。

打开应用、选择设备、首次配对，然后开始工作。再次连接应复用安全保存的凭据，
减少重复输入。设备发现只解决“找到谁”，不能替代授权。键鼠、常用快捷键、文字
和普通文件剪贴板应在已授权连接中形成连贯体验。回到被控电脑时继续原来的工作现场。

## 不应跑偏的原则

- 局域网直连，无账号、中心服务器、云中转或公网穿透。
- 共享和配对有明确授权，本机随时能停止共享、撤销访问。
- 远程画面优先，控制栏紧凑，连接后不常驻地址和密码编辑区域。
- 多端沿用同一套用词和流程，适配系统控件、快捷键与触控习惯。
- 日常使用不应依赖反复输密码、重置权限或手工删除旧版本。安装与升级属于产品工作。
- 以验证过的能力说明支持范围，源码存在不等于已经完成实机验收。
- 开发默认采用后台检查。抢焦点或注入真实输入的测试，需要约定测试时间并使用
  专门目标窗口，不能未经安排弹出测试窗口打断用户工作。

## 平台与边界

下一阶段完成 Windows ↔ macOS。Linux 后续支持桌面角色；Android、iOS/iPadOS、
HarmonyOS 首先作为桌面控制端。具体入口按平台能力显示，不能把手机控制端描述成
支持无人值守控制手机。各版本的能力和验收条件见路线图。

共享正常登录后的当前桌面，不承诺 FileVault 预启动解锁、通用登录/锁屏控制、
安全桌面绕过或新建远程登录会话。系统权限不能由应用静默授予。
SSH 和 CI 仅用于开发验证，不是普通用户的安装条件。

## 成功标准

在两台受支持设备安装应用，在目标设备开启共享，在另一台首次配对。
之后选中记住的设备即可连接。键鼠、剪贴板、文件、画质切换和重连稳定；断开会释放
按键并保留目标工作现场。发版前在真实受支持系统上完成验收。
