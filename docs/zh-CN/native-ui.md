# 原生界面进度

[English](../native-ui.md) · [设计方案](design.md) · [交付计划](v0.3.0-plan.md)

桌面设计已于 2026-10-10 审阅。本次是逐步接入的开发改动，不是新版本发布，
也不代表 v0.3.0 已完成实机验收。

两端源码统一为同一窗口中的**连接**、**共享此设备**、**设置**。
连接期间收起导航和凭据输入，保留画质、全屏、选项和断开工具栏。
共享页保留明确的开始/停止、隐藏密码和编辑/取消流程。传输协议、凭据身份与安装权限逻辑保留。

Windows 在连接表单旁显示发现的设备，继续使用现有安全记忆与已配对连接的剪贴板/文件流程。
共享页面复用现有生命周期控制器，不再显示第二个窗口。设置分组与会话选项保持一致。

Mac 使用原生窗口、系统字体及相同导航，控制端改用主窗口并保留 Command 按键处理。
Mac 控制端设备发现、持久配对记忆、反向剪贴板/文件和紧凑的首次配对对话框仍待补齐；
当前保留手动连接表单，避免把尚未实现的能力呈现为可用功能。

## 验证范围

Windows 已用 .NET 8 构建。不显示窗口的 WPF 检查覆盖中英文、820/1100/1440 像素布局、
导航、选择设备、取消修改密码、单窗口呈现、会话布局、角色互斥及监听端口清理。
检查使用独立凭据及模拟输入/采集适配器，不代表真实桌面输入、延迟或权限验收。

Swift 源码语法检查通过。开发 Mac 的 SSH 两次连接超时，因此**新版 Mac 界面尚未完成
Apple SDK 构建和安装后交互检查**；先前 SDK 结果仅适用于先前界面。不得据此创建新 tag/release。

`ClientChecks` 默认执行不显示窗口的检查。旧的显示窗口集成检查需要显式设置
`LOCALREMOTE_INTERACTIVE_CHECKS=1` 并约定测试时段；物理局域网输入检查仍独立手动启用。

见[检查记录](../../tests/results/native-ui-2026-10-10.txt)。接下来恢复 Mac 原生验证，补齐反向发现
及按会话管理的剪贴板/文件同步，再约定双机验收后打包 v0.3.0。
