# v0.3.0 交付计划

[第二轮设计](design.md)已确认，逐步接入客户端并保持已有远控链路的回归覆盖。
两端源码已实现本机名称编辑及认证后目标信息；视觉与设置整理、完整原生验收仍待完成。

[English](../v0.3.0-plan.md) · [产品方向](product.md)

记录日期：2026-10-11。这是范围与验收计划，不是发版公告；已有 tag 和下载包不变。

当前 Mac 已不在 Windows 开发机的同一局域网，暂没有可达的原生验证环境。按用户要求
停止直接 SSH 尝试，待明确提供可达环境后再恢复。继续 Windows 本地及可移植 Swift 检查，
Apple SDK 构建和原生验收保持待完成状态。

| 项目 | 当前证据 | 待完成 |
|---|---|---|
| Windows → Mac | 用户已反馈日常可用；Windows 加密回归用例 | 复现真实输入、文字/文件、重连与释放按键回归 |
| Windows 共享 | 捕获、编码与加密回环检查；源码预览 | Mac → Windows 真实应用输入、同一会话连续性 |
| Mac 控制端 | 先前 SDK/解码/加密/socket 基线通过；新配对与模型使用明确服务替身检查 | 新版 Apple SDK、钥匙串、安装后界面和双机验收 |
| 设备发现 | Windows 系统 DNS-SD 生命周期及 UDP 检查，两端发现接入源码、区分最近/本次发现 | Mac 原生 Bonjour 权限与真实双机发现 |
| 剪贴板/文件 | Windows 控制 Mac 方向已有实现 | 生命周期和授权跟随连接角色，两方向验证，无额外配对弹窗 |
| 安装升级 | 已有安装与权限恢复路径 | 实际签名下钥匙串、重启/升级、保留权限路径的原生验收 |
| 界面 | 设计已审阅，两端导航已接入源码；Windows 无窗口布局/生命周期检查通过 | 新版 Mac SDK 构建、安装后交互；补齐发现及首次配对流程 |

不能据此宣称真实系统输入、安装升级全部通过；色块解码也不是实时桌面延迟测量。
此前 Windows 测试窗口打断过用户工作，因此真实输入测试改为手动选择，并约定时间；
其他检查继续在后台进行。

## 执行顺序

1. **设计审阅（2026-10-10 已通过）**：固定产品方向，按已审阅方案逐步接入原生界面。
   手机和 Linux 页面仅作为后续平台规范，不属于 v0.3.0 已实现功能。
2. **v0.3.0-beta.1**：逐步统一两端入口，补齐反向设备发现，以及按角色管理的
   剪贴板/文件。保持 Windows → Mac 路径回归通过，沿用 Swift/C# 原生实现和现有认证局域网协议。
3. **原生验收**：两方向首次/再次连接，权限拒绝与恢复，断开释放输入，剪贴板授权
   与撤销，文件传输，画质切换，重连及资源释放。实际签名下验证安装升级，记录测量与失败项。
4. **v0.3.0 发版**：对齐版本、中英文说明、精确源码包、GPL 声明及校验和。
   验收通过后为测试过的提交打 tag 并发布 AtomGit release，不移动旧 tag。

v1.0.0 仍是桌面稳定发行目标；Android v1.1.0、iOS/iPadOS v1.2.0、Linux v1.3.0、
HarmonyOS 控制端 v1.4.0 保持既定路线及可行性验收。不需要为此重写应用或迁移 WebRTC。
