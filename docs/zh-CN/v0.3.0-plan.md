## 实机暂停期间的执行顺序

1. 按已有检查审查坐标/DPI、键盘/修饰键映射及释放路径。
   只修复具体缺陷或覆盖缺口，使用记录型系统接口，不注入真实输入。
2. 按实际临时签名方式审查选择器/启动/停止及钥匙串/升级状态。
   保留 bundle 身份和配对，不为无关修复重置权限或替换密码。
3. 审查两角色剪贴板/文件顺序、取消及重连归属。
   仅为已发现失败或缺失边界增加隔离检查。
4. 小范围提交 AtomGit，经现有镜像触发 GitHub Actions，
   完成原生编译及精确客户端包检查。本地编译可选，先准备一个已核验候选，再安排集中验收。

Windows 使用 FFmpeg 软件解码和 WPF 位图渲染。
[性能记录](performance.md)显示分配压力，正确性审查后可针对性复用缓冲区。
硬件解码/渲染改造需测量支持；该阶段无需 WebRTC、传输重写或大范围 UI 重设计。

## 版本顺序

- **alpha.3 / alpha.4**：历史预览，保留且不覆盖。
- **alpha.5**：最新已发布修正预览，实机待验收，AtomGit 附件镜像尚未齐全。
- **alpha.6：计划候选**：屏幕连接台界面、独立会话导航及集中验收；
  最终源码原生 CI/图片/包检查通过后再确定版本，不覆盖 alpha.5。仅改文档不提升 App 版本。
- **v0.3.0-beta.1**：P0 清零且两方向安装后的基础流程通过，列明剩余 P1。
  暂缓实测的预览需维护者明确授权，此前预览版的例外不自动继承。
- **v0.3.0**：完整[桌面清单](desktop-acceptance.md)、所需 P0/P1 修复和最终包检查通过。
- **v0.3.x**：兼容桌面修复；**v1.0.0**：整理支持的桌面体验，再扩展平台。

证据齐全前不承诺固定日期。支持临时签名/未公证 Mac 分发；
付费 Developer ID/公证可选，不决定稳定性；系统要求的首次打开、
辅助功能及钥匙串确认须准确说明。

恢复实测时，先准备精确 CI 包及可删除样例，在约定时长和专用目标上
先输入/权限、后剪贴板/恢复。用户恢复工作时立即停止，持续性能另行约定。
记录通过/失败/未运行，不反复让用户配合排查尚未完成的编码步骤。

遵循[已确认入口](entry-design.md)和[界面规范](interface.md)。
Android v1.1.0、iOS/iPadOS v1.2.0、Linux v1.3.0、HarmonyOS 控制端 v1.4.0
仍是未来目标。FileVault/登录前/安全桌面绕过、公网穿透及同时互相控制不在本阶段范围。
