# v0.3.0 delivery plan

[简体中文](zh-CN/v0.3.0-plan.md) · [Product direction](product.md) · [Roadmap](roadmap.md)

Updated **2026-10-14**. The goal remains one native application per desktop,
with **Start a connection / Accept connections**, controlling the current
logged-in session over a directly reachable private network.

## Current checkpoint

**v0.3.0-alpha.3** is published with Windows x64 and Apple Silicon Mac packages.
Native CI, isolated fixtures, unshown bilingual layouts, packaging and release
synchronization passed. Package source is **19b0a78**; later automation/doc commits
do not replace it. See [release evidence](../tests/results/automated-release-2026-10-14.md).

The owner reported both directions usable at earlier checkpoints. The earlier
controlled Mac → Windows pointer/wheel test failed; the DPI correction has
background coverage but no physical retest. Alpha.3 screen selection and installed
permissions/updates remain unverified. These are different evidence levels.

Interactive tests are **paused**. Continue review, isolated tests and CI without
installing/opening apps, accessing personal clipboards, injecting input or changing
permissions on either working computer.

## Remaining priorities

| Priority | Work | Available evidence | Completion condition |
|---|---|---|---|
| P0 | Correct input and safe release, both directions | Encrypted input/lifecycle fixtures; background DPI regression; earlier native pointer failure | Correct click/drag/wheel, letters/digits/keypad and target-native shortcuts; focus loss/disconnect/Stop release held input. |
| P0 | Mac capture access, credentials and updates | Picker cancellation/retry/cache fixtures, Apple SDK build and installer mocks | Installed selection/denial/retry and independent Accessibility work; credentials persist; two actual ad-hoc package upgrades have documented prompts/recovery without reset/reinstall loops. |
| P1 | Two-way text and regular-file clipboard | Both roles implemented; encrypted peers, recording clipboards and native synthetic network fixtures | Fresh Unicode text/files paste both ways with matching bytes/hashes; cancel/revoke cleans partial work and stale callbacks; no echo or loss of newer local copies. |
| P1 | Pairing, discovery and session recovery | Authentication/state, discovery lifecycle and unshown UI checks | Installed first/remembered pairing, editable errors, LAN discovery/manual IP, connected quality changes, Stop/restart and reconnect pass both ways. |
| P1 | Responsiveness and resource stability | Bounded queues and short synthetic resource checks | Repeatable two-device frame-rate/input-delay and CPU/memory baseline; sustained use and cleanup without accumulating workers/queues. |
| P2 | Final delivery | Native CI, exact source, six checksummed assets and automated release sync | Candidate packages/instructions match the tested commit; required results and limitations are recorded. |

P0 blocks recommending a desktop beta. P1 blocks the complete v0.3.0 daily-use
claim. Package publication alone clears neither gate.

## Work while physical tests are paused

1. Audit pointer coordinates/DPI, key/modifier mapping and release paths against
   existing tests. Fix concrete defects/coverage gaps with recording OS boundaries,
   never real input.
2. Review picker/start/stop and Keychain/update transitions for the actual ad-hoc
   distribution path. Preserve bundle identity and pairing; avoid incidental
   permission resets or password replacement.
3. Review clipboard/file ordering, cancellation and reconnect ownership in both
   roles. Add isolated coverage only for demonstrated failures or missing boundaries.
4. Submit focused changes to AtomGit; the existing mirror triggers GitHub Actions
   for native builds and exact packaged-client checks. Local compilation is optional.
   Prepare one verified candidate before requesting an acceptance period.

Windows uses FFmpeg software decoding and WPF bitmap rendering. The
[performance record](performance.md) shows allocation pressure; focused buffer
reuse can follow correctness review. Hardware decode/render work needs supporting
measurements. No WebRTC, transport rewrite or broad UI redesign is needed here.

## Version sequence

- **alpha.3:** published and immutable.
- **alpha.4, if needed:** concrete fixes, new native CI/packages and explicit
  outstanding acceptance. Documentation-only edits do not bump app versions.
- **v0.3.0-beta.1:** P0 resolved and basic installed workflow passed both ways;
  list outstanding P1 cases. A deferred-test preview requires explicit maintainer
  authorization; the alpha.3 exception does not automatically apply.
- **v0.3.0:** full [desktop checklist](desktop-acceptance.md), required P0/P1 fixes
  and final package checks pass.
- **v0.3.x:** compatible desktop corrections; **v1.0.0:** consolidated supported
  desktop experience before expanding platforms.

No fixed date precedes the remaining evidence. Ad-hoc/unnotarized Mac distribution
is supported; paid Developer ID/notarization is optional, not a stability gate.
Disclose system-required first-open, Accessibility and Keychain approvals.

When physical tests resume, prepare exact CI packages and disposable fixtures
first. Verify input/permissions before clipboard/recovery, with a dedicated target
and agreed duration. Stop when the owner resumes work. Schedule sustained
performance separately; record Pass / Fail / Not run rather than asking the owner
to repeatedly debug unfinished coding steps.

Follow the [approved entry](entry-design.md) and [interface conventions](interface.md).
Android v1.1.0, iOS/iPadOS v1.2.0, Linux v1.3.0 and HarmonyOS controller v1.4.0
remain future targets. FileVault/pre-login/secure-desktop bypass, public traversal
and simultaneous reciprocal control remain outside this milestone.
