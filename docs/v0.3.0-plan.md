announcement. Published tags and downloads remain unchanged.

[Revision 2](design.md) has been approved. Implement it incrementally while keeping
the working desktop path covered. Both sources now include local-name editing
and authenticated peer metadata; visual/settings convergence and full native
acceptance remain pending.

These results do not establish that real native input or installed update behavior
passed. Video decode fixtures do not measure live desktop latency. A Windows test
window interrupted the user's work; interactive input tests are now manual opt-in
and must be scheduled. Use background checks meanwhile.

## Delivery sequence

1. **Design review (approved 2026-10-10):** keep the product direction fixed; review the interactive
   proposal before replacing application UI. Mobile/Linux views are future design
   references, not v0.3.0 implementations.
2. **v0.3.0-beta.1:** incrementally unify the desktop entry points; complete reverse
   discovery and role-owned clipboard/files. Keep the working Windows → Mac path
   covered. Reuse native Swift/C# and the existing authenticated LAN transport.
3. **Native acceptance:** verify both directions, first/returning pairing,
   permission denial/recovery, held-input release, clipboard consent/revocation,
   transfers, quality changes, reconnect and resource cleanup. Test installation
   and update with the actual signing identity. Record measurements and failures.
4. **v0.3.0 release:** align versions, English/Chinese notes, exact-source packages,
   GPL notices and checksums. Tag the tested commit and create an AtomGit release
   only after the acceptance gates pass. Never move older tags.

v1.0.0 remains the stable desktop/distribution milestone. Android v1.1.0,
iOS/iPadOS v1.2.0, Linux v1.3.0 and HarmonyOS controller v1.4.0 keep their existing
roadmap targets and feasibility gates. No rewrite or WebRTC migration is needed
to deliver this desktop milestone.
