## 设计方向

让小工具显得精致、清楚、可预期。沿用“发起连接 / 接受连接”两个入口、单列设备、
配置后再开始、随时可停止的流程。视觉重点仍是“操作哪一块屏幕”，不增加说明性副标题、
永久侧栏、重复连接表单或装饰性的仪表盘。

沿用品牌蓝 `#5265EC`；文字 `#252D40`、辅助文字 `#637084`、浅色表面 `#F5F7FA`、
分隔线 `#E3E7EF`、成功状态 `#28745E`。Windows 使用 Segoe UI 与明确的微软雅黑中文映射，
Mac 使用系统字体。网页字体只是近似，不能证明原生字体已经验收。
主标题 26/25、弹窗标题 20、入口文字 19、正文 14、辅助标签 12；以 4px 为间距基准。
桌面预览 600 × 680，同时提供 420 × 568 紧凑检查。

首页保留已经批准的屏幕插图和图标，两个入口等大、整体居中。细微悬停反馈只响应用户操作，
没有持续闪烁、雷达、彩纸或装饰发光。普通页面单列排版；开始/停止与弹窗操作按钮留在滚动区外。

## 来自 Design Spells 的参考

用户提供了 [Design Spells](https://designspells.com/)。从其目录选择了以下方向，
自行实现适合本产品的交互；没有复制素材，也没有声称检查过这些应用的源码：

- [Sudoku a Day 面板过渡](https://designspells.com/spells/smooth-sheet-transitions-in-sudoku-a-day)：
  点击设备或修改配置时，用约 200ms 的轻量面板进入，保留操作上下文。原生端用本机面板实现。
- [Find My 状态过渡](https://designspells.com/spells/animated-transitions-in-find-my)：
  从设备列表进入配对时保留同一设备的名称、图标和地址；状态变化明确，避免“到底连上没有”。
- [Granola 图标反馈](https://designspells.com/spells/sidebar-icon-animation-in-granola)：
  反馈局限在当前操作附近。这里采用清楚的悬停/按下、状态文字和短暂复制提示，不因此增加侧栏。

评审时舍弃了大面积渐变背景、新品牌色、三维翻页和永久展开的设备详情。
这些变化不能让连接更快。保留一处有识别度的屏幕插图，其余控件保持清楚、克制。

## 具体变化

1. 首页只做角色选择。返回不停止接受连接；正在接受时有返回入口，已有远程会话时保留会话返回按钮。
2. 设备列表只保留一个“添加目标”。点击设备进入配对面板；手动输入 IP 时不凭空显示名称和系统。
   发现信息来自对方广播，不等于已经认证。示例记住的密码是 `Blue482X`，不读取真实钥匙串。
3. 连接模拟“正在连接 → 虚构桌面”；输入错误保留草稿。正在接受连接时，验证目标后再确认停止原角色。
4. 本机名称、IP、密码纵向排列，开始/停止在底部。生成只是八位草稿，取消不变，保存后停止接受，等待主动开始。
   IP 由系统提供，不作为应用可编辑设置。旧长密码兼容要求不因设计而改变。
5. Mac 的“屏幕录制”和“键盘与鼠标控制”分开。未允许屏幕录制不能开始；未允许控制则明确提示只能查看。
   允许与定位按钮只解释原生操作，不会在网页中授予权限。
6. 监听失败给出具体原因；端口详情收进故障排查，可复制诊断。示例端口冲突不能被原生端当成所有错误的统一原因。
7. 设置保留通用、连接设置、剪贴板、关于；标签页减少无关内容的堆叠。
   默认画质和当前会话画质分开；网页配置只在内存中暂存。
8. 文件传输用临时进度和取消入口，不添加永久工具栏，不再索要一次密码。64% 是静态示例，不是真实传输或性能指标。

会话页面仅示意紧凑控制，未完整重做远程桌面。没有引入同时双向控制、新平台或新协议能力；
原生实现仍须遵守角色冲突、停止及会话生命周期要求。
